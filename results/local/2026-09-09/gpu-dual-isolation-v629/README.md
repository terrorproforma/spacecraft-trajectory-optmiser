# Isolated-coordinate GPU dual correction, v629

This package preserves the completed standalone diagnostic and its controls. Thirteen tiny evaluations passed their expected outcomes. One real correction was accepted by the diagnostic; the independent saved-vector long-double and Decimal65 audits passed every unchanged original numerical gate. The originating PDHCG solve still has termination 2 (iteration limit), so this is not native solver qualification or an integrated speedup.

The generic detector handles only exactly isolated retained equality coordinates with zero original right-hand side and exactly zero initial residual. It preserves their original dual bits and removes their independent zero correction from QR. Nonzero targets, nonzero right-hand sides, shared rows/columns, and tiny second coefficients stay in the general problem. The full original stationarity, gap, cone, complementarity, rank/quality, strict subgradient-box and improvement checks remain. The earlier v626 implementation, failed build attempt, rejection controls and rejected real result are retained unchanged.

For the real v629 point, the original signed gap is approximately -5.10244e-17, leaving about 9.99999949e-10 to the unchanged 1e-9 absolute strip. Unscaled stationarity L2 decreased from 1.58711e-5 to 7.17619e-6; its infinity norm slightly increased from 5.05224e-6 to 5.06882e-6 while remaining below the fixed 1.0001e-5 bound. Original x, slack and retained cone dual bits stayed fixed, as did the four isolated equality duals. All 525 released epigraph pairs retain exact penalty sums and strict interior multipliers. Objective values are normalized convex-subproblem objectives, not kilograms.

The single real diagnostic measured 0.155032 s for evaluation, 0.224682 s for creation and 0.002431 s for destruction; its supervisor measured 0.520776 s for the entire process. These are distinct scopes. The 152.943 ms CUDA event span includes host guard gaps and is not a sum of kernel execution times. There was no repeated latency benchmark or end-to-end integrated comparison.

One separate Nsight run profiled the unchanged old v626 binary and preserved its flags=64 rejection. Nsight Systems 2024.6.2 reported that installed CUDA driver 13.2 was unsupported and used 12.8 tracing libraries. The trace contains host CUDA/library API activity; kernel and GPU memory activity were unavailable. The .nsys-rep and SQLite files are retained data artifacts. Their API durations must not be described as GPU kernel costs. No further profiling was performed.

The historical same-QP QOCO report records 32 iterations and a 0.093598 s solve-counter increment, plus separate update/residual counters. It does not provide a matched complete-latency measurement or that successor's standalone final-vector replay. The timing review and its exact saved dependencies are included. A later QOCO comparison, fleet work and mission results are outside this package. This tranche makes no fleet-score or SOTA claim.

## Verify without running a solver

Run `python audit_package.py --package . --expected-index INDEX_SHA256` with Python 3.10 or later, replacing INDEX_SHA256 with the published index hash. `--output /path/to/new-report.json` is optional and refuses to overwrite an existing file. The auditor uses only the standard library and reads the ZIP without extraction. It verifies exact membership, hashes, nested source archives, source-tree identities, original raw/report bindings, statuses, exclusions and profiling limitations. It never runs archived scripts, loads a native library, factors a matrix, propagates a trajectory, or calls a GPU.

`index.json` binds every evidence ZIP member and the top-level README, auditor and attributes. The index cannot hash itself; the separately supplied index hash is the trust anchor. The verification report is retained outside the package to avoid a circular hash. All archive paths are repository-relative. Extracting the ZIP into an empty directory restores the saved original audit dependency paths, but the static command above does not extract or repeat those numerical audits. Some historical reproduction scripts intentionally write new results and must not be run over the immutable evidence.
